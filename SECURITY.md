# Security Policy

The security and privacy of QuickQR users, merchants, and their customers are paramount. This document outlines our vulnerability disclosure policy and reporting process.

---

## Supported Versions

Only the latest release branch of QuickQR receives security updates:

| Version | Supported |
| :--- | :--- |
| `1.x` (latest / `main`) | :white_check_mark: Supported |
| `< 1.0` | :x: End of Life |

---

## Reporting a Vulnerability

If you discover a security vulnerability in QuickQR, please report it privately. **Do NOT disclose security vulnerabilities in public GitHub issues, discussions, or social media.**

### How to Report

Please report security issues using **GitHub Private Vulnerability Reporting**:

1. Navigate to the repository on GitHub: [https://github.com/amanxthink11/quickqr](https://github.com/amanxthink11/quickqr)
2. Click on the **Security** tab.
3. Select **Report a vulnerability** under the Advisories menu.
4. Provide a detailed summary including:
   - Description of the vulnerability and its potential impact
   - Step-by-step reproduction instructions or proof-of-concept
   - Affected files and components
   - Recommended remediation or patch, if known

If GitHub Private Vulnerability Reporting is unavailable, you may contact the maintainer directly through the contact details on [https://amanxthink11.com](https://amanxthink11.com).

---

## Our Security Commitments

When a vulnerability report is received:

1. **Acknowledgment**: We acknowledge receipt of your vulnerability report within 48 hours.
2. **Investigation**: We verify the issue, determine severity, and assess affected components.
3. **Remediation**: We prepare a fix and test for regressions.
4. **Coordinated Disclosure**: We issue a security release alongside an advisory crediting the reporter (unless anonymity is requested).
